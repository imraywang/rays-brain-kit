# Ray's Brain Kit

一套跑在你自己电脑上的个人知识系统：**Obsidian 库结构模板 + AI 采集管线 + 本地知识工作台**。

收集不是问题，判断才是。这套系统让 AI 做机器该做的事（抓取、提炼、打分、生成审核卡），
把最终判断权留给人（长期知识与候选选题分别判断，也可以同时保留；另有暂缓和可恢复清理），
所有数据都是本地 Markdown 文件，Obsidian 随时可编辑，没有第二套数据库。

三个组成部分，可以独立使用：

| 组件 | 位置 | 依赖 |
|---|---|---|
| 库结构模板 | 目录骨架由 bootstrap 生成 | 无（纯文件夹约定） |
| 本地知识工作台 | `50-系统/40-自动化/知识仪表盘/` | 仅 Python 3 标准库 |
| AI 采集管线 | `50-系统/40-自动化/知识采集/` | Python 3 + [Codex CLI](https://github.com/openai/codex) + [xurl](https://github.com/xdevplatform/xurl)（可选） |

## 五分钟看到工作台

```bash
git clone https://github.com/imraywang/rays-brain-kit.git my-brain && cd my-brain
python3 50-系统/40-自动化/知识仪表盘/bootstrap.py . --demo   # 生成目录骨架 + 演示数据
python3 50-系统/40-自动化/知识仪表盘/server.py               # 打开 http://127.0.0.1:8765
```

你会得到一个本地工作台：今日焦点、审核队列（支持 `J/K` `1-5` 键盘流）、
八列进展看板（待判断 → 等待处理 → 候选选题 → 可续写 → 写作任务 → 草稿 → 已发布 → 待复盘）、
全库搜索、灵感速记、实时刷新。浏览器"安装应用"后体验与原生 App 一致。

把这个目录用 Obsidian 打开，它同时就是你的笔记库。

## 启用采集管线（可选，逐项开启）

1. 复制 `50-系统/40-自动化/知识采集/config.example.json` 为同目录 `config.json`。
2. **网页剪藏**：Obsidian Web Clipper 存入 `30-资料/40-网页剪藏/`，无需额外配置。
3. **X 收藏**：安装 xurl 并完成 OAuth，`config.json` 填 `x_app`。
4. **手机分享**：按 `手机分享设置.md` 建 iCloud 投递箱，填 `mobile_inbox`。
5. **AI 审核卡**：安装 Codex CLI 并登录，管线会把新资料提炼成审核卡送进工作台。
6. **定时运行**：按 `50-系统/40-自动化/定时任务/安装说明.md` 装 launchd 任务。

不装管线也可以手工往目录里放笔记，工作台照常工作。

## 与 rayskills 的分工

[rayskills](https://github.com/imraywang/rayskills) 里的 `ray-obsidian` skill 负责**复刻同款知识库**：候选选题、
写作任务、图文母稿、口播母稿、发布反馈和长期知识各自分层，并对已有库做零覆盖增量适配
（结构契约：`ray-content-v2`）。本仓库负责**搭配使用的本地可视化工作台与采集自动化**。

两者兼容：本仓库 bootstrap 建的最小骨架能被 ray-obsidian 识别为兼容库并补齐模板；
ray-obsidian 初始化的库也可以直接被本工作台和管线使用。只用其中一个也完全成立。

如果你已经在用 Claude Code / Codex 这类 Agent，还有第三种进入方式：
[rayskills-lab](https://github.com/imraywang/rayskills-lab) 里的 `ray-dashboard` skill
携带本仓库工作台的资产副本，由 Agent 完成安装到已有知识库、诊断和升级。
资产以本仓库为发布源；能力先在真实知识库验证，再同步到这里，最后进入 `ray-dashboard` 的资产副本。

## 设计原则

- **Markdown 是唯一真源**：没有数据库，没有双向同步问题，十年后文件还在。
- **AI 提炼，人判断**：严格满足边界的高把握知识可以先保存为初始知识，但是否进入候选选题仍由人决定。
- **注意力有期限，来源不丢失**：待审核和候选默认各有 7 天注意力窗口；超期退出当前队列，但原始资料、审核记录和已沉淀知识继续保留。
- **写入窄且可恢复**：工作台只做明确列出的审核、状态流转、起草、登记和正文编辑，没有永久删除。
- **默认本地**：工作台默认只监听 127.0.0.1；手机访问只通过用户明确启用的私有网络通道。
- **零第三方依赖**：工作台是纯 Python 标准库 + 原生 JS，clone 即跑，随意魔改。

## 目录约定

```
00-入口/   工作台与总览        10-创作/   灵感 → 候选 → 写作任务 → 母稿
20-知识/   长期可复用的知识     30-资料/   剪藏、X 收藏、调研
40-发布/   平台成品与反馈       50-系统/   本套工具与文档
60-素材/   图片音频（不进 git） 90-归档/   历史与可恢复的待清理
```

文件夹布局可改：见 `知识仪表盘/config.example.json`。审核卡协议（状态、五个动作和注意力窗口）
是管线与工作台之间的契约，改动需两侧同步。

## 当前闭环

- 新资料先形成审核卡；系统每天默认只突出 3 条最值得判断的内容。
- 高把握、知识价值明显高于写作价值的完整知识单元，可以先自动保存为 `seed`，但不会自动进入候选选题。
- 待审核 7 天仍无人判断时，已有初始知识的按知识归档，其余只保留来源。
- 候选选题 7 天仍未立项时，先补齐长期知识，再关闭候选；不会自动建立写作任务。
- 发布后通过 `反馈复盘/` 获取 24 小时和 7 天数据、生成判断清单，并把人工确认的结论回写知识。
