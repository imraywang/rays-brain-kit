# 反馈复盘自动化

> **暂停口播视频反馈**：视频号、抖音、小红书的数据拿不到时，可以新建 `config.json` 写入 `{"video_feedback_paused": true}`。开启后登记口播发布照常记平台、链接和时间，但不建反馈卡；每天的快照会把仍在跟进的视频反馈卡以 `verdict: paused` 关闭。X 长文和公众号反馈不受影响。默认不开启。

把发布反馈的复盘拆成三层，对应脚本 `feedback_snapshot.py` 一次运行的三个阶段：

1. **机械层（脚本做）**：扫描 `40-发布/00-内容反馈` 中 pending 的反馈卡，到期后用 xurl（复用知识采集的 `xurl_path` / `x_app` 配置）抓 X 公开指标，填入 24 小时 / 7 天快照，只填空值、不覆盖手动数据。微信公众号拿不到数据接口，`wechat_data_status` 自动降级为 `unavailable`，不再阻塞判断。
2. **判断层（人做）**：每次运行重建工作台 [[00-入口/10-工作台/反馈复盘]]，数据就绪的反馈列出指标、机械信号解读和建议结论。你只勾选一个结论（继续深挖 / 停止此角度 / 换角度重写 / 归档），可改「理由」行。建议每周日与知识地图整理放同一个半小时。
3. **闭环与止损（脚本做）**：下一次运行时，已勾选的结论写回反馈卡（`status: 复盘完成`）、追加到「回写去向」的长期知识的「发布反馈」小节；到期超过 30 天仍无复盘的卡自动关闭为 `无需复盘`（`close_reason` 注明样本不足）。

## 运行

```
python3 50-系统/40-自动化/反馈复盘/feedback_snapshot.py
```

定时任务 `com.ray.feedback-snapshot` 每天 17:50 运行（先于 18:00 的健康日报，让日报反映最新数据）。

## 边界

- 只有 X 指标可自动抓取；口播视频（视频号 / 抖音 / 小红书）仍需手动补数，缺链接的卡会列在工作台「等待数据或链接」区。
- 转发口径 = 转推 + 引用。
- 信号解读是机械启发式，只做建议；结论必须人勾选后才生效，同一条勾选多个结论会被跳过并提示。
- 抓取失败不阻塞其他卡，错误列在工作台「本次运行提醒」。

## 测试

```
python3 -m unittest discover -s 50-系统/40-自动化/反馈复盘
```
