# 爆款雷达新手指南：从跑起来到看懂实现

爆款雷达每天从抖音、小红书拉一批「作者粉丝少，内容却爆了」的作品，放进知识工作台的「📡 雷达」页。你看一眼，觉得哪条值得做，点「加入选题」，它就变成一张候选选题卡片。

这份指南分两部分：

- 第一部分把它跑起来，大约 10 分钟。
- 第二部分按顺序读代码，搞清楚每一步是怎么实现的。

仓库地址：https://github.com/imraywang/rays-brain-kit

---

## 第一部分：跑起来

### 第 1 步：先看一页总览

打开 [README.md](README.md)（[GitHub 上的地址](https://github.com/imraywang/rays-brain-kit/blob/main/50-系统/40-自动化/爆款雷达/README.md)），先弄清三件事：

- 数据从哪来。
- 存在哪。
- 一条作品怎样才算「爆款」。

### 第 2 步：把仓库拉到本地

```bash
git clone https://github.com/imraywang/rays-brain-kit.git my-brain
cd my-brain
python3 50-系统/40-自动化/知识仪表盘/bootstrap.py . --demo   # 生成目录骨架和演示数据
```

需要 Python 3.10 以上和 curl，这两样 macOS 都自带。不用装任何 pip 包。

### 第 3 步：注册 TikHub，拿到 API Key

雷达不自己爬平台，数据全部来自第三方接口 TikHub，按调用次数收费。

1. 打开 https://user.tikhub.io 注册并登录。
2. 在用户后台创建一个 API Key，然后充值。默认配置每轮约 $0.16，$5 能用很久。新账号有少量免费额度，抖音接口能用这部分额度。
3. 接口文档在 https://docs.tikhub.io 。想在线试调某个接口，用 https://api.tikhub.io/docs 。

### 第 4 步：把 Key 写进本机配置

Key 不放进仓库，放在本机的状态目录里：

```bash
mkdir -p ~/.local/state/rays-brain
cat > ~/.local/state/rays-brain/tikhub.json <<'EOF'
{
  "api_key": "这里换成你的 Key",
  "base_url": "https://api.tikhub.io"
}
EOF
chmod 600 ~/.local/state/rays-brain/tikhub.json
```

想放到别的目录，就设环境变量 `RAYS_BRAIN_STATE=/你的目录`，脚本和工作台都会改用那里。

### 第 5 步：先空跑，再真跑

```bash
python3 50-系统/40-自动化/爆款雷达/radar.py fetch --dry-run   # 只列出要调哪些接口、大概花多少钱，不扣费
python3 50-系统/40-自动化/爆款雷达/radar.py fetch             # 真正拉一轮，1–3 分钟
python3 50-系统/40-自动化/爆款雷达/radar.py status            # 看这一轮拉回多少条、多少条过了门槛
```

### 第 6 步：在工作台里看结果

```bash
python3 50-系统/40-自动化/知识仪表盘/server.py
```

浏览器打开 http://127.0.0.1:8765 ，点左侧栏的「📡 雷达」（手机上在底部导航）。页面上方按页签分开：全部新题、抖音、小红书、清单类、已加入、不合适。每张卡片可以这样处理：

- **加入选题**：在 `10-创作/10-灵感/20-候选选题/` 生成一张候选卡片，写清爆款参照（原帖链接、数据）和你填的角度。
- **不合适**：隐藏这条，可以顺手屏蔽这个作者。
- **重新获取**（右上角）：在后台再跑一轮 `radar.py fetch`，效果和第 5 步一样。

### 第 7 步：改成你自己的关键词

打开 [radar_config.json](radar_config.json)，把 `douyin.keywords` 和 `xiaohongshu.keywords` 换成你所在领域的词。门槛先别动，跑几天，看过门槛的条数再调。每个字段的意思见 README 的「配置」一节。

## 第二部分：看懂实现

整条链路只有两个文件：

- 采集和打分在 [radar.py](radar.py)。
- 页面和按钮在知识仪表盘的 `server.py` 与 `static/app.js`。

建议按下面的顺序读。每一步都写了要找哪个函数，在文件里搜函数名就能找到。

### 第 8 步：一轮采集是怎么跑的（`radar.py`）

[radar.py 在 GitHub 上的地址](https://github.com/imraywang/rays-brain-kit/blob/main/50-系统/40-自动化/爆款雷达/radar.py)

| 顺序 | 函数 | 做什么 |
|---|---|---|
| 1 | `run_fetch` | 总入口：读配置 → 拉抖音 → 拉小红书 → 补查粉丝 → 打分 → 合并保存 → 记一行运行日志 |
| 2 | `Budget` / `tikhub_call` | 每次调用前先记账，到了 `max_calls` 就停，已经拉到的照样保存；调用走 curl 子进程 |
| 3 | `fetch_douyin` + `douyin_item` | 调抖音低粉爆款榜（每个关键词 2 页，7 天窗口），把返回字段统一成一种格式 |
| 4 | `fetch_xhs` + `xhs_item` | 调小红书笔记搜索（综合排序 + 一周内，每个词只拉第 1 页） |
| 5 | `xhs_published_at` | 用小红书笔记 id 的前 8 位十六进制算出发布时间，不依赖接口自带的时间筛选 |
| 6 | `enrich_xhs_fans` | 小红书搜索结果里没有粉丝数，给最有希望的几位作者补查，结果缓存 30 天 |
| 7 | `score_item` | **核心判断**：算互动、爆款倍数（互动 ÷ 粉丝）、天龄，再判断是否过门槛、是不是清单类、要不要屏蔽 |
| 8 | `merge_items` | 按「平台:作品 id」去重，保留首次发现时间，更新最新数据 |

用到的三个 TikHub 接口：

| 接口 | 单价 | 文档 |
|---|---|---|
| `POST /api/v1/douyin/billboard/fetch_hot_total_low_fan_list` 抖音低粉爆款榜 | $0.001 | 在 https://docs.tikhub.io 搜 `low_fan` |
| `GET /api/v1/xiaohongshu/app_v2/search_notes` 小红书笔记搜索 | $0.01 | 搜 `search_notes` |
| `GET /api/v1/xiaohongshu/app_v2/get_user_info` 小红书作者信息 | $0.01 | 搜 `get_user_info` |

### 第 9 步：点按钮之后发生了什么（`radar.py` 后半段）

| 函数 | 做什么 |
|---|---|
| `radar_view` | 给工作台整理要展示的列表：新条目只留过了门槛或倍数待定的，屏蔽的不显示；你处理过的条目也留着，供「已加入」「不合适」页签用。按爆款倍数从高到低排，倍数待定的放最后 |
| `adopt_item` + `candidate_note` | 「加入选题」：生成候选卡片的 Markdown，frontmatter 写 `kind: topic-candidate`、`origin: radar` |
| `mark_item` | 「不合适」「已看」「恢复」，记到 `feedback.json` |
| `cover_bytes` | 封面代理：平台图片有防盗链，统一由本机下载缓存后再给页面，只放行 douyinpic.com 和 xhscdn.com |

### 第 10 步：工作台怎么接上它（`server.py` / `app.js`）

[server.py 在 GitHub 上的地址](https://github.com/imraywang/rays-brain-kit/blob/main/50-系统/40-自动化/知识仪表盘/server.py)

- `radar_module`：按文件路径懒加载 `爆款雷达/radar.py`。没有这个目录时，雷达页显示「未安装」，其余功能照常。
- `radar_payload` → `GET /api/radar`：给页面的数据。
- `radar_action` → `POST /api/radar/action`：三个按钮。
- `start_radar_run` → `POST /api/radar/run`：「重新获取」，后台派生进程，同一时间只跑一个。
- 前端在 [static/app.js](https://github.com/imraywang/rays-brain-kit/blob/main/50-系统/40-自动化/知识仪表盘/static/app.js) 里，搜 `radar`。

### 第 11 步：用测试验证自己的理解

```bash
python3 -m unittest 50-系统/40-自动化/爆款雷达/test_radar.py
```

[test_radar.py](test_radar.py) 里每个测试都是一个小例子，不联网：

- 低粉爆款怎么过滤、同一条作品被几个关键词命中时怎么合并。
- 小红书只给过了初筛的作者补查粉丝，而且有缓存。
- 预算用完时，已拉到的数据会不会丢。
- 加入选题只生成一张卡片，点两次不会重复。
- 屏蔽作者和恢复。
- 过期条目自动清理，已加入选题的保留。
- 封面代理只放行平台图床。

改了门槛或规则以后，先跑一遍。

## 为什么这样设计

这些决定都来自上线前的实测：2026-10-26 一共调用 44 次，花了约 $0.12。

- **为什么用 TikHub，不自己爬？** 小红书一识别到机器操作就弹扫码登录，自己维护爬虫的成本比接口费高得多。
- **为什么看「爆款倍数」，不只看点赞？** 大号随便发都有几万赞，对小号没有参考价值。「互动 ÷ 粉丝」高，说明是选题本身在起作用，别人照着做也有机会。
- **为什么抖音不带垂类标签？** 实测加了「科技」「科普」标签，结果反而又旧又弱：点赞中位数只有几百，最老的近两年。只用关键词加 7 天窗口，结果都在 1–14 天内。
- **为什么关键词要窄？** 「AI」「为什么」这类宽词，出来的多是 AI 短剧、情感 MV。具体的词（活动话题、工具名）才对口。`exclude_words` 再挡掉一部分噪音。
- **为什么小红书自己算发布时间？** 接口的「一周内」筛选，只在综合排序和按时间排序时生效，按点赞排序就失效了。笔记 id 里自带创建时间，自己算更可靠。
- **为什么小红书每个词只拉 1 页？** 实测第 2 页和第 1 页重复 7–8 条，要扩大覆盖面就多加关键词，别靠翻页。
- **为什么数据不进笔记库？** 每轮几百条、过期很快，放进笔记库只会变成噪音。只有你点了「加入选题」的那条才写成笔记。

已知还没解决的问题，见 README 的「已知边界」。
