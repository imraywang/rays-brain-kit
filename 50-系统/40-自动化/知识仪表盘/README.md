# Ray's Brain 本地知识仪表盘

这是 Obsidian 的本地入口层，不是第二套笔记系统。

## 快速开始（新 vault 或试用）

```bash
python3 bootstrap.py ~/my-vault --demo   # 建目录骨架 + 演示数据，重复执行安全
RAYS_BRAIN=~/my-vault python3 server.py  # 指向该 vault 启动工作台
```

不带 `--demo` 只补齐目录骨架，既有文件一律不动。

## 配置

- `RAYS_BRAIN`：vault 路径（默认取本目录的上上级，即仪表盘随 vault 存放的场景）。
- `RAYS_BRAIN_STATE`：运行时状态目录（默认 `~/.local/state/rays-brain/`）。
- 目录布局：复制 `config.example.json` 为本目录 `config.json`（或用 `RAYS_BRAIN_CONFIG` 指定路径），
  改成你自己的文件夹名。所有键必须是 vault 内的相对路径，未知键会直接报错。
- 审核卡协议（frontmatter 的 `status` 值与「人工审核」五个选项）由采集管线定义，不属于布局配置。

仪表盘默认读取这些创作目录：

- `10-创作/10-灵感/20-候选选题`：分别展示待选择的 `candidate` 和已有文章但仍有剩余角度的 `partially-published`。
- `10-创作/10-灵感/90-选题储备`：保留暂时不推进的选题，不进入当前候选列。
- `10-创作/20-写作任务`：展示尚未完成的 `writing-task`、`content-task` 或现有 `content-pack`。
- `10-创作/30-文章草稿`：展示图文母稿（`draft` / `article-draft`）。从长文改出来的口播稿也放这里，但跟着母稿走，不在母稿看板上单独占位。
- `10-创作/25-口播草稿`：展示以口播起稿、没有图文母稿的 `oral-script`（ray-kb 写的 `koubo-draft` 同义）——这种稿子自己就是母稿，不收进来就一次都不会出现。
- `40-发布`：展示已发布内容，但不把下面的反馈笔记算成发布成品。
- `40-发布/00-内容反馈`：读取发布后的反馈记录，并统计仍待复盘的数量。

候选选题先按 `priority_score` 排序，同分时再按 `writing_value_score` 排序。卡片会展示
`knowledge_value_score`、`writing_value_score` 与 `timeliness`；也兼容知识库里已有的同义字段。

## 启动

在 Finder 中双击 `启动知识仪表盘.command`，浏览器会自动打开：

<http://127.0.0.1:8765>

终端启动方式：

```bash
python3 server.py
```

终端窗口保持打开时，仪表盘会持续运行。关闭窗口或按 `Control+C` 即可停止。

## 能做什么

- 查看知识流转、审核积压、候选选题、写作任务、草稿、发布反馈、长期知识和最近活动。
- **工作台内阅读**：点任何卡片、搜索结果或最近笔记，在侧抽屉里直接读全文（Markdown 渲染，含双链跳转、图片、表格、勾选列表）；双链可在抽屉内继续下钻，`←` 返回上一篇；`↗` 兜底跳 Obsidian。
- 默认只看今日优先的 3 条，也可以切到低成本清理或全部队列；审核动作可以在抽屉里边读全文边完成。
- 对满足严格边界的资料，系统会先生成初始知识并在卡片上标明“知识已自动保留”；它仍不会替你决定是否进入候选选题。
- 进入待审核区 7 天仍没有人工判断的卡片会退出当前队列：已有初始知识的按知识归档，其余只保留来源；原始资料和审核记录都不删除。
- 候选选题进入候选池 7 天仍未立项时，会先从原审核记录补齐长期知识，再关闭候选；不会自动建立写作任务，也不会删除任何来源。
- 来源卡里明确记录的个人笔记、实践和判断会显示“含个人背景”，并沿审核、知识、候选和成稿包继续传递；外部作者观点不会被当成个人经历，正式使用前仍需确认范围。
- 普通卡有五种审核选择：仅进入长期知识、仅加入候选选题、同时进入知识和选题、暂缓、待清理。知识已经自动保留的卡片会收敛成“只保留已有知识”或“再加入候选选题”，避免留下互相矛盾的记录。旧卡片里的「仅保留为写作素材」会按「加入候选选题」兼容处理。
- 把审核选择写回原卡片，继续交给已有的半小时自动流程处理。
- 已勾选的卡片显示在「等待自动处理」列表中，流程执行前随时可撤回。
- **状态流转**：候选可暂缓/恢复/关闭，写作任务可沿阶段推进或退回、放弃后可重新激活，发布反馈可一键标记已复盘；全部流转由 `../board_protocol.json` 声明，带 mtime 冲突检测，可在 toast 内 `U` 撤回，并追加到状态目录的 `logs/dashboard-actions.jsonl` 审计日志。
- **候选立项**：抽屉里点「立项为写作任务…」或把候选/可续写卡拖到「写作任务」列，填一句角度即调用 `knowledge_ingest.py promote` 建立成稿包。
- 进展看板八列追踪内容流转：待判断 → 等待处理 → 候选选题 → 可续写 → 写作任务 → 草稿 → 已发布 → 待复盘。前两列互相拖拽勾选或撤回；候选/可续写拖到写作任务列即立项。
- 搜索整个知识库，结果在抽屉内直接打开。
- **正文编辑**：阅读面板点 ✎ 进入编辑（⌘S 保存、Esc 取消），只改正文、页首属性原样保留，带 mtime 冲突保护；属性变更仍走状态流转。
- **速记分流**：快速把灵感追加到 `10-创作/10-灵感/inbox.md`；首行带链接的速记自动投进链接收件箱，交给采集管线抓取。
- **管线面板**：侧栏「采集」一行点开——最近活动、待处理来源、未解决错误（可标记已解决）、管线日志尾部、「立即采集」（后台派生一轮 `knowledge_ingest.py run`，与 30 分钟定时任务互不阻塞但建议少用）。
- **AI 任务队列**：写作任务的阅读面板点「排入 AI 起草队列」，追加到 `50-系统/40-自动化/AI任务队列.md`（按任务去重）。这是给 Claude Code 的交接清单：/ray 会话读取此文件，处理一条勾掉一条、行尾补产物链接。
- **Codex 起草**：写作任务的阅读面板点「让 Codex 起草这篇」，后台派生 `../AI执行/draft_worker.py`（单并发防重入）：Codex 在只读沙箱里读成稿包与关联材料，产出经 schema 校验的 JSON，由 worker 落盘为 `status: ai-draft` 的待审初稿并回写任务状态、勾销队列。进行中状态在管线面板可见；完成后草稿列自动出现新卡并推系统通知——这是「工作台发起操作、结果传回看板」的第一条完整闭环。
- **登记发布**：草稿或正式稿的阅读面板点「登记发布…」，平台是必选项，公开链接和发布时间是可选项——缺正式稿时自动从草稿归档（`article-published`/`video-published` + `draft_source`），然后调用 `../发布归档/record_published.py` 写平台状态、建反馈卡、回写源头书签，最后把草稿与成稿包移出活跃区。多平台就登记多次。公开发布本身始终是人的动作；链接和时间以后需要追溯时再补，不影响已发布状态。
- 页面实时刷新：审核卡、候选选题、写作任务、草稿、发布或运行状态有变化时自动更新，不用手动刷新。
- 键盘审核流：`J / K` 切换卡片，`1–5` 对应五种处理，`U` 撤回，`O` 在抽屉内读全文（再按关闭），`⇧O` 打开 Obsidian，`/` 或 `⌘K` 搜索。
- 顶栏 🔔 可开启系统通知：页面不在前台时，新审核卡到达或采集异常会推送通知。

- **少跳出去**：审核卡和阅读面板优先打开 `source_file` 指向的本地原文存档，原帖链接退为次要入口；站外链接一律标出域名并带 ↗，Obsidian 链接用 ◆ 标识。流程区和指标卡都能点，跳到审核区或看板对应列。
- **Obsidian 嵌入在网页里还原**：阅读面板渲染 `![[笔记]]`、`![[笔记#标题]]`、`![[x.base#视图]]` 和 `query` 查询块（实现见 `obsidian_views.py`，只支持本库用到的子集，认不出的条件会提示以 Obsidian 为准）。
- **发布面板**：成品、母稿的阅读面板按平台列出状态、正式链接（可复制）、草稿后台、封面，以及反馈卡等关联笔记；有 `video_file` 的直接播放本地视频。
- **网页复盘**：反馈卡的阅读面板可以下结论（写回反馈卡并同步「反馈复盘」清单），也能逐项填平台数据。
- **口播工作区**：口播稿的「待确认」逐条勾选（普通列表勾上会改写成任务行），录完点「标记已录制」。正文里的任务勾选框都可以直接点。
- **发布表现**：按正式稿的 `series` 归组，比较各系列的平均浏览和收藏率；**待修问题**：把健康日报里能逐条修的问题列出来，点开即改。

## 新增 API（v3–v5）

- `GET /api/note?path=` 或 `?link=`：读笔记全文与属性；`link` 按 Obsidian 双链规则解析（先路径后文件名）。
- `GET /api/asset?path=` 或 `?link=`：按扩展名白名单送出 vault 内图片附件。
- `GET /api/pipeline`：管线状态（最近活动、待处理、未解决错误、日志尾部、AI 队列）。
- `POST /api/note/transition`：`{path, to, expected_mtime_ns}`，按看板协议校验后定点改写 frontmatter（`mtime_ns` 为字符串透传，避免 JS 数字精度丢失）。
- `POST /api/note/save`：`{path, body, expected_mtime_ns}`，替换正文、保留页首属性。
- `POST /api/promote`：`{path, angle}`，子进程调用采集管线的 promote 命令。
- `POST /api/pipeline/resolve-error`：`{at, message}`，在管线 state.json 中标记该错误已解决。
- `POST /api/pipeline/run`：后台派生一轮采集，进行中拒绝重入；输出在状态目录 `logs/manual-run.log`。
- `POST /api/intent`：`{path, action: "draft"}`，把写作任务排入 AI 任务队列（按任务去重）。
- `GET /api/embed?link=`：嵌入内容（笔记、标题小节或 `.base` 视图）；`GET /api/query?q=`：执行 Obsidian 查询块。
- `GET /api/media?path=&field=video_file`：按笔记属性送出本地视频（支持 Range），只认 `video_file` 字段和常见视频格式。
- `POST /api/note/task`：`{path, line, checked, expected_mtime_ns}`，只改正文里那一行勾选。
- `POST /api/feedback/metrics`：`{path, values: {行号: 值}, expected_mtime_ns}`；`POST /api/feedback/verdict`：`{path, verdict, reason}`。

## 安装成"应用"

页面支持 PWA。Chrome / Edge 地址栏右侧点"安装"，或 macOS Safari 用 文件 → 添加到程序坞，
即可获得独立窗口和图标。配合开机自启的 server，日常体验和原生应用一致。

## 手机访问

两条通道，Safari 打开后「添加到主屏幕」即可当 App 用：

- **Surge Ponte（推荐，Surge 常开不用切换）**：Mac 和 iPhone 的 Surge 各自开启 Ponte
  （同一 iCloud 账号），Mac 端设好设备名后，手机访问 `http://<设备名>.sgponte:8765`。
  Ponte 在 Mac 端把该域名解析到 127.0.0.1，服务端无需额外监听，`.sgponte` 后缀已在
  Host/Origin 白名单内。
- **Tailscale**：`--tailnet` 启动参数（`启动知识仪表盘.command` 已默认带上）会额外在
  本机的 Tailscale 地址上开一个入口，手机连 Tailscale 后用 MagicDNS 域名访问。注意
  iOS 上 Surge 与 Tailscale 的 VPN 隧道互斥，二者只能同时开一个。Tailscale 没在跑时
  自动跳过，只保留本机访问。

## 安全边界

- 默认只监听本机地址，不向局域网或互联网开放。`--tailnet` 只额外绑定 Tailscale 网卡地址：
  可达性等于你 tailnet 里的自有设备，局域网其他设备与公网仍然连不上；Host 与 Origin
  白名单同步只放行本机地址、本机 tailnet IP 和 MagicDNS 名。
- 不提供永久删除。
- 所有写操作限定为：灵感/链接追加、审核卡勾选、协议声明过的 frontmatter 状态流转、走既有管线的立项、只动正文的编辑、AI 队列追加，以及管线错误标记。
- 正文编辑与状态流转都带 mtime 冲突检测：文件刚被其他程序改过时拒绝写入，提示刷新重试；编辑永不触碰页首属性。
- AI 请求只入队不执行：长任务交给 Claude Code 会话消费队列文件，工作台保持轻量常驻。
- Markdown 文件和属性仍是唯一真源。
